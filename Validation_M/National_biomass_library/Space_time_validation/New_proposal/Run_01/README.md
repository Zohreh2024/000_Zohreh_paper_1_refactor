# Run_01 — verified mature only

One change from Run 0: `--maturity "verified mature"`. **327 sites instead of
600.** Everything else identical — NVIS-constrained matching, `eq1_of_mean`, all
174 predictors, PCA to 95%, 99th-percentile cutoff.

No analysis code was written for the matching. The parent folder's
`Step_03_match_and_validate.py` is run exactly as it stands, with the one flag.

## How the parent folder is protected

`Step_03` names its outputs from the feature set, constraint and averaging order
— **not** from the maturity classes. So running it with a different `--maturity`
overwrites the published Run 0 results.

`Step_01` copies every file `Step_03` will touch into a private backup, runs it,
takes the results, then restores the backup and **verifies each file against a
content hash**.

> An earlier version trusted `git status` / `git checkout` for this and **failed
> silently**: `matches*.csv` is in the repository's `.gitignore`, so git never
> reported it as modified and could not restore it. Run 0's match table was
> overwritten and had to be regenerated by re-running `Step_03`. Git can only
> protect what git tracks, and half of what `Step_03` writes it does not. The
> backup is now file-level and unconditional.

## Why this run exists

The two maturity classes carry almost the same observed biomass and behave
completely differently:

| class | n | ratio | ρ | observed AGB | **AGB per m²/ha BA** | **plot area** | max DBH |
|---|---|---|---|---|---|---|---|
| verified mature | 327 | 0.61 | 0.49 | 117.5 | **7.3** | **0.40 ha** | 68 cm |
| likely mature | 273 | 0.34 | 0.39 | 109.8 | **17.4** | **0.24 ha** | 40 cm |
| *pooled (Run 0)* | *600* | *0.49* | *0.42* | *112.4* | *10.2* | *0.24 ha* | *52 cm* |

The last three columns are properties of the **observation**, not of M′ — a
difference there is a difference in the data. 17.4 Mg of biomass per m²/ha of a
stand's own basal area is at the top of what a stand can physically carry, and
those sites were measured on plots **40% smaller**. A per-hectare figure from a
smaller plot is the same few trees divided by less ground.

## Result — the hypothesis is confirmed

Eight scenario-windows, analogue-found sites only:

| | Run 0 | Run 1 | change |
|---|---|---|---|
| median ratio | 0.465 | **0.557** | **+0.096** |
| Spearman ρ | 0.269 | **0.371** | **+0.103** |
| sites | 600 | 327 | −273 |
| width of the 95% interval on the ratio | 0.163 | 0.270 | **+66%** |

The likely-mature half *was* dragging the headline numbers down.

Two windows move the other way — SSP370 and SSP585 2070–2099 — and should not be
read: they retain **41 and 14** sites of 327. Halving the sample makes those
windows worse, not better.

## What it is worth, once both nulls are read

A null drawn from the same 327 sites is easier to beat for exactly the reason
the runs are — the sample is cleaner. So the honest measure is the **gap between
the runs and their own null**:

| | null ratio | null ρ | gap (runs ρ − null ρ) |
|---|---|---|---|
| Run 0 vs NVIS-constrained null | 0.445 | 0.205 | **+0.064** |
| Run 1 vs NVIS-constrained null | 0.478 | 0.286 | **+0.084** |
| Run 0 vs unconstrained null | 0.210 | 0.029 | **+0.240** |
| Run 1 vs unconstrained null | 0.228 | −0.056 | **+0.426** |

> Against the constrained null the gap improves by only **+0.020**, against a
> headline ρ gain of **+0.103**. **Four fifths of what Run 1 appears to buy is
> shared with its own null** — the sample getting cleaner, not the matching
> getting better. Against the unconstrained null the gap nearly doubles, which
> is the other half of the picture: the method plainly has skill and Run 1
> increases it.

Both nulls were necessary to reach that reading. Against the unconstrained null
alone Run 1 looks like a large improvement; against the constrained null alone
it looks like almost none.

## What to conclude

- **Confirmed**: removing the likely-mature half raises the ratio +0.096 and ρ
  +0.103.
- **But the mechanism is plot size, not maturity.** Those sites are not less
  mature — they are more inflated per-hectare figures. The maturity threshold is
  acting as a proxy for a data-quality problem.
- **So the better fix is a plot-area floor, not a stem-size threshold.**
  Filtering on maturity discards 273 sites to remove an inflation a minimum plot
  area would remove directly, without also discarding the genuinely mature
  stands in that group. Worth running as its own one-change test.
- **Report Run 1 as a sensitivity, not a replacement** — four fifths of the gain
  is shared with the null, precision falls 66%, and two windows become unusable.
